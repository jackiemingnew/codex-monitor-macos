# ADR 0019：详情外观跟随系统并允许手动覆盖

- 日期：2026-09-13
- 状态：接受；真实 UI 验收单独记录
- 取代：ADR 0018 中“详情固定浅色”的边界，其余布局与数据证据约定保留。

## 背景

用户认可当前浅色信息层级，但希望白天浅色、夜间深色。长期常驻的监测界面应尊重系统外观和用户选择，而不是维护两套功能或另一套昼夜调度。

## 决策

详情外观提供“跟随系统／浅色／深色”，默认跟随系统，使用现有设置的草稿、保存和取消流程。macOS 自身处于自动外观时负责切换时间，应用不新增定时器、不修改系统偏好，也不保证某个固定小时自动切换。

使用 AppKit 动态语义颜色，并将手动覆盖限制在独立详情 NSPanel 的 appearance。跟随系统时清除覆盖；不改变 NSApp.appearance、不重建 SwiftUI 视图树，避免重置选中页面、折叠状态和键盘焦点。设置窗口继续使用系统语义色；菜单栏和收起胶囊的原有高对比度方案保持不变。

浅色保留暖白底与现有品牌强调。深色使用独立炭灰表面、柔和白字、较亮蓝色和绿色，而不是简单反色或重新叠加半透明灰色。所有详情页、图表与 Tooltip 共用同一套动态颜色，不复制数据视图。

## 备选方案

- 固定晨间/夜间时刻：与系统作息可能冲突，需要额外调度和设置，暂不采用。
- 全局 NSApp 外观覆盖：会连带影响菜单栏和其他窗口，范围过大，暂不采用。
- 两套独立 UI：布局与数据口径易漂移，不采用。

## 后果与验证

仅增加一个本地展示偏好和现有窗口外观更新；不新增扫描、网络请求、模型调用、业务缓存或权限。

测试覆盖偏好的缺省/非法值/持久化、动态颜色在 Aqua/Dark Aqua 下的真实解析、重要文本对比度及深色胶囊隔离。构建、签名、安装与进程验证和真实 520pt 视觉、系统切换、手动覆盖、键盘及 VoiceOver 验收分别报告；不可用的真实验收保持 UNVERIFIED。
